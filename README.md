# Mini Instagram

Mini Instagram - это проект в формате React SPA, который имитирует сервис для просмотра фото: вход по `userId`, профиль пользователя, альбомы, фотографии, комментарии и глобальные настройки интерфейса.

Проект демонстрирует роутинг, контроль доступа, типизированную загрузку данных, клиентское хранение состояния, переиспользуемые UI-примитивы.

## Demo

[Открыть приложение](https://grinder21.github.io/mini-instagram/)

## Что умеет приложение

Сценарий работы выглядит так:

1. Пользователь входит по числовому `userId`
2. Приложение загружает профиль этого пользователя
3. Пользователь открывает свои альбомы
4. Внутри альбома можно просматривать фотографии
5. На странице фотографии доступны комментарии
6. В настройках можно изменить тему и плотность сетки
7. Сессия и настройки сохраняются между перезагрузками страницы

Интерфейс построен поверх публичных mock API.

## Основные возможности

- Авторизация по `userId` с сохранением сессии в `localStorage`
- Защищенные маршруты для приватных страниц
- Проверка владельца для маршрутов профиля
- Страница профиля с информацией о пользователе и списком альбомов
- Страница альбома с сеткой фотографий
- Страница фотографии с комментариями
- Глобальная страница настроек
- Поддержка светлой и темной темы
- Сохранение пользовательских настроек интерфейса
- Состояния загрузки, ошибки, пустого результата, `403` и `404`
- Адаптивный layout для desktop и mobile

## Источники данных и внешние сервисы

Проект не требует собственного backend и использует только публичные сервисы:

- `JSONPlaceholder` - пользователи, альбомы, фотографии, комментарии
- `Picsum` - обложки альбомов и превью изображений
- `Pravatar` - аватары пользователей и комментаторов

## Архитектура

Проект организован в стиле Feature-Sliced Design.

```text
src/
  app/        # app shell, providers, routes, layout
  entities/   # доменные сущности и контексты приложения
  features/   # изолированная логика загрузки данных
  pages/      # route-level страницы
  shared/     # общий ui, хелперы и generic api hook
```

### Роли слоев

`app`

- композиция приложения
- настройка роутера
- route guards
- общий layout

`entities`

- доменные типы и проверки данных
- контекст авторизации
- контекст настроек

`features`

- изолированные hooks для загрузки альбомов, фотографий, комментариев и пользовательских коллекций

`pages`

- сценарии экранов и page-level композиция UI

`shared`

- generic fetch hook
- служебные утилиты
- хелперы для генерации изображений
- переиспользуемые UI-примитивы

## Маршруты

| Маршрут       | Описание                            | Доступ                             |
| ------------- | ----------------------------------- | ---------------------------------- |
| `/`           | точка входа, редирект по auth state | public                             |
| `/login`      | вход по `userId`                    | только для guest                   |
| `/user/:id`   | профиль пользователя                | только владелец                    |
| `/users/:id`  | алиас страницы профиля              | только владелец                    |
| `/albums/:id` | страница альбома                    | authenticated, с проверкой доступа |
| `/photos/:id` | страница фотографии                 | authenticated                      |
| `/settings`   | настройки приложения                | authenticated                      |
| `/forbidden`  | страница запрета доступа            | authenticated                      |
| `/404`        | страница не найдена                 | public                             |

### Guards

В роутинге используются три типа guard-компонентов:

- `GuestGuard` не дает авторизованному пользователю снова попасть на страницу логина
- `AuthGuard` защищает приватные маршруты и отправляет гостя на `/login`
- `OwnerGuard` пускает на страницы профиля только текущего авторизованного пользователя

Дополнительно часть проверок выполняется и на уровне feature-хуков, например при загрузке альбомов, которые должны принадлежать текущему пользователю.

## Управление состоянием

### Авторизация

Авторизация здесь намеренно легковесная:

- пользователь вводит числовой `userId`
- этот `id` сохраняется в `localStorage`
- `AuthProvider` загружает пользователя по API
- если пользователь не найден, локальная сессия очищается

Такой подход позволяет запускать проект без backend и при этом показать реалистичную frontend-логику авторизации.

### Настройки

Глобальные настройки находятся в `SettingsProvider`.

Что сохраняется:

- `theme`: `light` или `dark`
- `grid`: количество колонок в галерее

С чем синхронизируются настройки:

- `localStorage`
- CSS-класс темы на `document.documentElement`
- CSS custom property для управления сеткой

## Подход к загрузке данных

В проекте используется универсальный hook `src/shared/api/useGetData.ts`.

Что он делает:

- собирает request URL с query-параметрами
- поддерживает условную загрузку через `enabled`
- отменяет незавершенные запросы при размонтировании или смене зависимостей
- возвращает предсказуемый контракт: `data`, `isLoading`, `error`

Поверх него построены более узкие hooks:

- `useGetUserAlbums`
- `useGetAlbum`
- `useGetAlbumPhotos`
- `useGetPhoto`
- `useGetPhotoComments`

## Быстрый demo-сценарий

Чтобы быстро посмотреть проект:

1. Запустить приложение
2. Открыть `/login`
3. Войти под одним из demo id: `1`, `3`, `5`, `8`
4. Открыть профиль
5. Перейти в альбом
6. Открыть фотографию
7. Изменить тему и сетку в настройках
8. Перезагрузить страницу и убедиться, что сессия и настройки сохранились
